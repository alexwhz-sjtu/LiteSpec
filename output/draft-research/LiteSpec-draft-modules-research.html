调用边界与参数归属

训练：Adapter 准备 ModelInputs / Supervision
  → FSDP 包装的 ComposableTrainingModel
      → draft_model: Context → Backbone → Proposal
      → objective: DraftOutput + Supervision → TrainingOutput
  → 现有 runner: backward → 全局归一化 → optimizer.step

推理：ComposableDraftModel（相同顶层 forward）
  → Context → Backbone → Proposal
  → 推理侧采样/验证/状态提交或回滚

顶层 modeling.py 只编排三个部署模块。Proposal 的 teacher-forcing、score 或 sample 模式由输入显式声明；一次顶层调用允许串行头内部递推。DraftState 分为 context/backbone/proposal 子状态，约定逻辑位置、缓存借用/所有权、commit/rollback，不强迫每种 attention 共用同一物理 KV 布局。

包装器成员固定叫 draft_model，匹配 checkpoint 的 draft_model.* 提取规则。可训练融合必须在 FSDP forward 内执行；adapter 只能做无参数准备。冻结 target embedding/head 通过既有 shared components 处理，不复制为新可训练参数。Objective 首版无参数。

01 / Context

三个 injection preset，共用一条并行 draft 数据流

信息注入模块只负责为每层提供 context。所有 draft 层都并行处理 anchor + mask tokens；head 的顺序过程单独保留。将“目标信息获取”和“目标信息变换”拆开，避免某个 injection 假定只能从 hidden 取特征。

1.1 DFlash：精确保留现有基线

ct = RMSNorm(Linear([htarget,j₁t; …; htarget,jLt]))
Context KVℓ = AttentionProjectionℓ(c)；Draft-block KVℓ = AttentionProjectionℓ(xℓ)

融合结果对 draft 层共享；context 与 block K/V 使用原有共享投影。对应 DFlashDraftModel.fc + hidden_norm 和 attention 的 context 分支。模块抽取时保留 state-dict key 转换与 normalization / RoPE 次序。↗ litespec/modeling/draft/dflash.py:685 ↗ litespec/modeling/draft/dflash.py:386 ↗ litespec/modeling/draft/dflash.py:448

1.2 DFlare：原方法包含两项结构变化

αℓ,j = softmaxj(Aℓ,j)
cℓ,t = RMSNorm(Σjαℓ,jhtarget,jt)
Context 与 draft block 使用各自的 K/V 投影

第一版 injection=dflare 同时启用逐层 learned fusion 与分离 context/draft 投影；保留两个内部开关供消融，但命名为 DFlare 的 preset 必须包含两者。融合权重是训练参数，不是逐 token 的动态 gate。MHA 对照官方实现；MLA 将 context 与 block 的 KV-down、KV-up、K-RoPE 分支分别实例化，Q 和输出投影仍属于共同 attention core。这是明确的 MLA 适配定义，参数预算单独记录。↗ angelspec/models/draft/dflare.py:189 ↗ angelspec/models/draft/dflare.py:41 ↗ DFlare · 2026-06

1.3 KVShot KV-only：多层 target KV 降维为 draft context KV

采用 KVShot 的 linear projection 方案：同一绝对位置、所选各 target 层的 K 分别拼接，V 也分别拼接；用两套 learned 矩阵投影到一层 draft attention 所需的 KV 维度。prefix 直接使用投影出的 KV，不经过 DFlash 的 hidden fusion，也不再通过一次 hidden→KV projection。↗ KVShot · 2026-04

ktstack = concatj(flatten_heads(Kj,ttarget))
vtstack = concatj(flatten_heads(Vj,ttarget))
Kℓ,tctx = reshape(PK,ℓ ktstack)
Vℓ,tctx = reshape(PV,ℓ vtstack)
约定具体实现
拼接轴先统一布局为 [N,S,Hkv,dK] / [N,S,Hkv,dV]，flatten heads，再沿特征维合并 target 层。保留 S 个 token，绝不把 L 层变成 L×S 个位置。
投影维度K 输入维度为 ΣjHkvj·dKj，输出为 Hkvdraft·dKdraft；V 独立计算。固定 hidden d 不要求 KV 维度等于 d。
逐层参数每个 draft 层拥有自己的 PK,ℓ / PV,ℓ。这是扩展到多层 parallel draft 的确定设计；不引入共享/不共享参数的额外首版搜索轴。
并行查询Q 来自当前并行 block hidden；block-local K/V 由 MHA 或 MLA 的现有投影产生；attention 的 keys/values 组合为 [projected target prefix | own block]。
上下文 normalizationKV projector 输出就是最终 context KV；不额外套 hidden RMSNorm 或再投影。Q 与 block-local K 的原有 normalization 保留。以后如增加 context-K norm，必须另命名为实验变体。
信息来源KV-only backbone 不输入 target hidden。Soft CE / TV / NLA / BV 所需 target logits 属于监督信息，仍允许获取。

1.4 KVShot 的 RoPE 与 MLA 适配要写明

target cache 的 K 通常是 post-RoPE。KVShot 原文同时比较“直接线性投影”和“投影后重施 RoPE”。第一版默认锁定 rope_policy=projection_only，对应你要求的线性融合降维；保留同一注入族下的 projection_reapply_rope 精确消融。两者均不擅自 inverse-RoPE。重新施加的是目的 attention 的 RoPE 与正确绝对位置；cache 元数据记录当前状态，避免 backend 再重复旋转。↗ KVShot · 2026-04

MHA 直接把投影输出接到 expanded context K/V。MLA 仍使用现有低秩 Q 和 block-local KV，但 context adapter 输出 dK=qk_nope_dim+qk_rope_dim、dV=v_head_dim 的 expanded KV；若启用 reapply-RoPE，只旋转 destination 的 RoPE 部分。这个 KVShot×MLA 是有明确维度与位置语义的并行适配，不宣称其为 KVShot 原论文已报告的实验。↗ litespec/modeling/draft/dflash.py:448 ↗ litespec/modeling/draft/dflash.py:277

1.5 Target KV 获取与缓存生命周期

扩充 TargetTrainingOutput，允许同时返回指定层 KV、监督 logits 与位置元数据。HF backend 先提供连续、可校验的 expanded cache；SGLang 的分页/量化缓存通过 backend adapter 提供只读视图或必要的显式转换。首个验收 target 限定为普通 MHA/GQA、可导出 expanded KV 的模型；不承诺直接读取压缩 MLA target cache。↗ litespec/modeling/target/training_target_model.py:14

  1. 训练 target 先计算全序列 KV，但每个 anchor 的 prefix view 严格排除未来 token，并按 document ID 隔离。
  2. 推理冻结 target；仅在确认 token 后，获取/刷新该段 target KV 及其 projected draft context KV。target cache 只读借用，projection 结果是 draft 自有缓存。
  3. 当前 mask block 产生的临时 K/V 不直接充当下一轮已确认 context。下一轮 context 来自所选 injection 对已确认 target 信息的变换。
  4. KV projection 参数需要梯度；target KV detach。训练过程中不能跨 optimizer step 复用带旧参数的投影结果；推理参数固定时可增量缓存。
KVShot 路径的预算：它生成独立的 projected draft KV，仍有额外 prefix cache 与投影开销。SWA 可以把该缓存限制到 W，但不能将该路线称为 target KV 零复制。
02 / Attention and cache

MHA / MLA 保留；SWA 改为历史 KV 截取

2.1 首版窗口的精确含义

令 anchor 位于绝对位置 a。历史 context KV 中只保留 [max(document_start,a−W), a)，不含 anchor；当前 block 的 anchor 与 B 个预测位置全部保留。每个 query 读取同一份历史切片，以及同 block 全部 local KV。W 是历史缓存预算，不含当前 block，因此有效 attention KV 长度最大为 W+Q。

历史可见：document_id 相同 ∧ max(doc_start,a−W) ≤ s < a
块内可见：key_block_id = query_block_id（所有 offset）
不添加 key_offset ≤ query_offset；不添加 a+query_offset 的移动下界

例：a=100、W=4、B=3。所有 block queries 都读取历史位置 96…99，以及当前 block 位置 100…103；位置 100 的 query 也允许读取 101…103 的 mask 表征。后续 query 不再把 96、97 逐个排除。

2.2 需要实际修改的三处

位置改动验收
训练 mask删除旧 SWA 的 draft_offset≤query_offset 条件；历史下界改成 a−W，不含 query offset；只允许自己的 block。SDPA 与 Flex 路径一致。改变后方 mask token 表征，前方 query 输出允许变化；未来 target KV 与其他 anchor 的 block 仍不可见。↗ litespec/core/attention_masks.py:58
推理历史 cache确认 prefix 后只保留最近 W 个 context KV；拒绝后先回滚，再裁剪已确认历史。临时 block KV 单独放置，不在 block 处理中间裁剪。历史缓存长度≤W，当前块完整；拒绝后的下一轮与完整 prefix+同窗口 reference 对齐。↗ litespec/modeling/draft/dflash.py:277
Backend dispatch用显式 mask / 截取后的 KV 实现窗口，is_causal=False；禁止再把旧 sliding_window 参数传给一个会施加逐 query sliding/causal 规则的 kernel。Eager、SDPA、Flex 都得到同样可见集合。某 backend 不能表达该语义时，配置时报不支持，不静默换语义。↗ litespec/modeling/draft/dflash.py:277

缓存裁剪后绝对位置继续增长，不能把 KV 位置重编号为 0…W−1。DFlash / DFlare 的 hidden→KV 与 KVShot 的 target-KV→projected-KV 都受同一窗口策略管理。训练可先实现逻辑 mask reference，再按每个 anchor gather 最近 W 个 context KV，真正减少 attention 工作量；多 anchor 的窗口不可根据整个 batch 的最后一个 anchor统一截取。

配置版本：新语义命名为 history_window_bidirectional_block_v1。旧 checkpoint 中 sliding_attention 含 block-causal 含义，加载时必须按版本转换或明确拒绝；不能在未记录版本变化时改变旧实验结果。

4.1 NLA：逐 token 计算与 wrapper 一起锁定

采用已查到的固定源码版本 src/speculators/losses/eager.py::neg_log_acceptance_loss：softmax 在 FP32 中计算，overlap clamp 到 1e-5 再取负 log。没有 LK-hybrid 的混合项，也不加 annealing。保留 losses/utils.py::loss_function 的 masked sample mean；有位置 decay 时只进入分子，分母仍为 mask count+ε，不偷换为 Σ(position weights)。↗ src/speculators/losses/eager.py:145 ↗ src/speculators/losses/utils.py:269 ↗ LK Losses · 2026-02

LNLA = meann[(Σa,imn,a,idiℓNLA,n,a,i)/(Σa,imn,a,i+10⁻⁵)]

这是一项明确的实现来源选择：NLA 核心是论文的 LK-α，完整 wrapper 来自本轮所核对的 Speculators 版本。既然要保留实现，checkpoint 必须记录该 recipe ID 与源码 SHA；不能仅写 loss=nla 后任由训练引擎选择另一种分母。

4.2 D-PACE：移植官方分支，不增加归一化变体

CEi=−log qi(yi)；q̃i=(1−a)exp(−CEi)+a
Pj=Πi≤jq̃i；wi=stopgrad(Σj≥iPj)
LD-PACE=Σn,a,imn,a,iwn,a,iCEn,a,i/N
  1. 原 _dpace_weight 的 smoothing、cumprod、flip-cumsum-flip、mask 语义保持。无效 slot 对乘积是 1、对后缀求和是 0；计算权重放入 no_grad。↗ specforge/core/dflash.py:234
  2. 默认 smoothing a=0.5；CE 本身保持原实现，不增加 label smoothing。输入 loss mask 语义与原分支一致，不因“优化”改变 dtype / clamp / epsilon。↗ D-PACE · 2026-05
  3. 归约分母固定 N：N 是输入样本数，不是 N×A。若某样本没有有效 anchor，它的分子是 0，但不擅自从 N 中删除。

4.3 BV：锁定原文主实验 recipe 与数值细节

原文理论目标 1−E[accepted_length]/B 与主实验的训练 recipe 需要区分。第一版 loss=bv 固定为主实验的 vocabulary-integrated、annealed block-log，不同时提供 sampled-label、population-log 或简单 CE 加权替代版。↗ Block Verification-aware Loss · 2026-09

r0=1；ri=ri−1·qi(yi)/pi(yi)
A0=1；Ai=min(Ai−1,ri)
Āi=Σvmin(Ai−1pi(v),ri−1qi(v))
log θi=log Āi；λi=stopgrad(softmaxi(β·log θi))
annealing-gradient surrogate：−Σiλilog θi
β=1 后的 block-log：log B−log(ΣiĀi)

prefix r/A 沿 sampled target path 更新，当前 score 积分掉当前 token；不能把 Ā 当下一位置的 prefix state。r/A 使用 FP32 log-space 并保留 prefix 梯度。annealing 阶段权重 λ detach，但 log scores 与 prefix state 的梯度不 detach；日志另记录原文的 power-mean objective，避免把 gradient surrogate 的标量当成它。E[−log τ̂] 与 −log E[τ̂] 仍分别命名。

原文 recipe 项第一版固定规则
β 退火前三个 epoch 线性从 0 升至 1，之后固定 1。若做原文六 epoch recipe，后面三个 epoch 是 block-log 阶段；改变 epoch 总数不自动把它换成“前 50% step”。
Ramp 数值 profileDFlash 原文 profile 把 score floor 到 10⁻⁶；DSpark profile 的 annealed log-score 不用此 floor。完整记录 profile，不能把两份实现揉成一个默认 ε。
Block-log 数值log summands floor = −80；summed length estimate floor = 10⁻⁶；固定原文顺序，不新增稳定化操作。
Head profile 对应none preset 使用 DFlash profile；Markov / DSpark RNN 使用 DSpark profile。DLite 可运行同一 dense BV 目标，但必须显式选择一个原文数值 profile；这是迁移实验，不宣称原文已经验证 DLite。
块选取首版只使用固定 B、连续有效且在同一监督文档/回答段内的完整 block，排除 anchor 与尾部不完整块；跳过数记录为指标。mask 不能把不连续 token 拼成一个 prefix。
平均与权重完整 block loss 求有效 block 均值；不额外叠加指数 position weights 或 D-PACE weights。
Proposal 支持集BV + selector 配置直接报错。首版也不将 top-K / top-P 截断后的 proposal作为 BV训练配置；以原文 full-vocab、T=1 recipe 验收。

teacher 轨迹必须由与 ratio 分母 p 相同的 target 采样分布生成；首个复现配置采用原文 T=1、full vocabulary。BV 需要 block verification 才与原目标对齐；greedy 或 token verifier 的评估可以另报，但不替代 block-verifier 验收。BV 的 logits 来自最终 corrected / replacement head，teacher-forcing 前驱必须与该 target 轨迹一致。

实现来源状态：NLA 与 D-PACE 已定位到公开可调用源码，可做逐值与梯度对照；BV 本轮只有论文与 Appendix A.3/A.4/B.4 的具体实现描述。按这些细节建立 reference，但在取得作者实现并完成比较前，验收标记为“原文 recipe 复现，尚未完成作者源码一致性验证”。

4.4 数据、分块与分布式归约

Objective 内部记录 recipe_id、scope 与 native per-sample / per-block values，公共出口统一使用现有 TrainingOutput 与 RatioTerms。Hard/Soft CE、KL、TV 可保持当前位置加权归约；NLA 保留先样本归一再平均；D-PACE 聚合原始分子与样本 N；BV 聚合有效 block loss 与 block count。↗ litespec/core/outputs.py:18 ↗ litespec/core/chunking.py:35

gradient accumulation 与 DDP 使用这些计数对齐完整逻辑 batch，不能对不等 batch 的局部平均再无权平均。RNN 的 teacher-path logits 先完成块内状态更新；D-PACE/BV 不允许按 prediction token 把 prefix 链切断。vocab chunk 只改变内存处理，不改变全局 softmax、BV prefix state 或原 reduction。第一版用 eager reference 固定数学，再替换优化实现。
