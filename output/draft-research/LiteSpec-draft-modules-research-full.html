1.1 DFlare：可最先集成的注入变化

αℓ,j = softmaxj(Aℓ,j)
cℓ,t = RMSNorm(Σj αℓ,j htarget,jt)
Kctxℓ = WctxK,ℓ cℓ，Kdraftℓ = WdraftK,ℓ xℓ（V 同理）

官方当前实现保留 [batch, context, target_layers, d] 的 hidden stack；融合参数 [draft_layers, target_layers]；循环中用 einsum("t,bstd->bsd") 生成该层 context。初始化按相对层深给出距离先验；context normalization 在该实现中是同一个模块。无需重新执行 target，但多层特征捕获、传输和训练驻留成本必须计入。↗ angelspec/models/draft/dflare.py:189

集成点：将 DFlashDraftModel.fc 封装为默认 ContextProvider；DFlare provider 返回逐层视图，并让 attention 接收本层 context。投影共享关系由 attention 的 context adapter 控制。第一轮分别跑：只改融合、只拆 K/V 投影、两项同时启用，才能分清收益来源。不要因为 hidden size 相同，就假定不同 target 层 hidden 的统计分布或 K/V 基底相同。

1.2 直接 target KV：接口难点在 target 侧

现有 TargetTrainingOutput 只公开 hidden、可选 logits、input IDs 与 mask，没有 KV view。直接复用 KV 首先要扩充 target backend 的输出与生命周期，而不是仅改 draft attention。训练时即使预先算出整条 target KV，也必须按 anchor 屏蔽未来位置。↗ litespec/modeling/target/training_target_model.py:14

  1. 缓存格式：显式记录 target 层号、KV heads、key/value dim、dtype/量化 scale、位置与页表。hidden_size=d_target 不保证 KV 格式兼容。MLA latent cache 与普通展开 K/V 是不同类型。
  2. 位置语义：标记 pre_rope / post_rope / latent+rope。target post-RoPE K 不能再旋转一次；draft Q/K 必须延续 target 的位置、θ、scaling、旋转布局和 Q/K normalization 约定。
  3. 只读借用：已验证 prefix 的 target cache 作为只读 view；本轮临时 draft block KV 单独管理。拒绝后 crop / 回滚由 verifier 驱动，不能污染 target 缓存。跨请求与 packed document 的边界必须随 view 传递。
  4. 层映射：第一版采用一层 draft 对应一层 target。跨层 KV concat、投影会产生新张量，应另标为 target_kv_projected，不能再宣传“无额外 prefix KV”。
迁移边界：GliDe 是 target KV 的直接读取，但通过独立 cross attention；H-Spec 是混合骨干中的原位 prefix KV 复用；DFlash 是 hidden→新 KV。三者都可能被笼统叫“KV injection”，实验记录应把它们明确区分。

1.3 值得保留但后置的扩展

KVShot 的 hybrid 可以抽象为：普通输出 n 与 KV cross-attention 输出 o 构成 Δ=o−n，再由门控对 Δ 作校正。它是输出级融合，不等于 DFlare 的 target 层权重。H-Spec 则展示了 last_hidden → initial_state 这一注入位置；若未来纳入，应扩展 backbone state 初始化契约，而非硬塞进 context_hidden。这些迁移是设计建议，当前 LiteSpec 尚无对应可直接切换的插件。

2.1 MHA / GQA：已有投影路径可以继续用

Q 只来自 draft tokens；context hidden 与 draft hidden 共用 K/V 投影，沿序列维拼接。MHA 通过 n_kv_heads=n_q_heads 得到；GQA 允许多个 Q heads 共享 KV heads。现有 recipe 会为 MHA 设置 heads 相等。保持 d 不变仍可变化 heads / head dim / KV heads，这些属于 attention 内部设计，不是跨模块 hidden width 搜索。↗ litespec/modeling/draft/dflash.py:386 ↗ litespec/training/recipes/_dflash_common.py:314

2.3 SWA：当前语义要写入实验元数据

令 anchor 绝对位置为 a、query 块内偏移为 o，现有 full mask 允许 target 位置 s<a，以及同一 draft block 的全部位置。启用 SWA 后，target 侧再要求 s ≥ a+o−(W−1)，draft 侧变为 draft_offset ≤ o。当前 mask 没有再对 draft 侧加窗口下界；当 W 小于 block 宽度时尤其要注意这一差异。↗ litespec/core/attention_masks.py:58

设计建议：把 context_window、intra_block=full|causal、window_applies_to=context|all 拆开。旧 SWA 用具名 preset 复现；“仅缩小 context window”的实验不能同时悄悄改变 block 内因果性。所有判断用逻辑位置和 block/document ID，不能把 packed 张量的物理列号当绝对位置。

2.4 DSA：已读官方 indexer、MLA 与 FP8 kernel

It,s = Σh wt,h · ReLU(⟨qIt,h, kIs⟩)
St = TopKs∈合法位置(It,s)
Attention 在 St 上执行主 Q/K/V 的归一化和加权聚合

官方 Indexer 从低秩 Q 表征 qr 经 wq_b 生成多头 index Q，从 hidden 经 wk + LayerNorm 生成共享 index K；对部分维度施加 RoPE，再旋转 activation 并做 FP8 量化。weights_proj(x) 给出逐 query / head 的标量权重；kernel 执行点积、ReLU、乘 head 权重、求和与量化尺度还原。mask 在 top-k 前加入，最后取 token 索引。注意权重投影没有 softmax，不应自行改成正权概率。↗ inference/model.py:435 ↗ inference/kernel.py:200

公开配置给出 index_n_heads=64, index_head_dim=128, index_topk=2048；这是大 target 模型配置，不是推荐给小 draft 的默认值。当前官方参考 MLA.forward 仍先生成 dense attention scores，再 scatter 一个 top-k mask；它用于表达正确语义，不能据此宣称实际主 attention 已降至 O(BK)。indexer 本身也要扫描候选 context。↗ inference/config_671B_v3.2.json:1 ↗ inference/model.py:498

论文训练分两步：先保持 dense attention、冻结主网络训练 indexer，使其分布匹配主 attention 跨 heads 汇总后的分布；再切换稀疏 attention，继续在选中集合上训练 indexer。indexer 输入 detach，使用独立 KL 信号，主网络走自己的语言模型目标。只加 top-k 不加 indexer 训练，不能算完整复现。↗ DeepSeek-V3.2 技术报告 · 2025-12

移植到 parallel draft 的具体算法（建议，不是现成官方配置）
  1. 复用 block-aware 合法性规则：每个 anchor 只能读取它的 prefix 与指定 block 内位置；先屏蔽不可见位置，再选 top-k。
  2. 对 context 生成 index K，并与 context KV 同生命周期缓存。direct-target-KV 模式若没有相应 hidden，不能直接执行官方 wk(hidden)：须额外捕获 hidden，或提出从 target K/latent 生成 index K 的新方案。
  3. 初版只对 prefix 做 top-k，保留 block-local tokens；这有利于短块依赖，但属于你的改版，配置与论文复现要区分。若需原版选择策略，再对所有合法 keys 统一 top-k。
  4. 先用 dense mask 对照证明数学输出一致，再做 gather / 专用 sparse kernel。候选数不足 K 时排除 padding，处理全空行；top-k 本身不提供可靠的离散选择梯度。
  5. 在 draft 的小 B 与实际上下文长度上测量 indexer、selection、attention 三段耗时。短 context 下可能收益为负，实验应允许回退到 dense。
03 / Backbone operator

DFlash2 卷积应该是“子层包装器”

DFlash2 作者介绍的是短程、动态、depthwise causal convolution：当前位置与前一位置混合；每 16 channels 共享一份动态修正，基础 kernel 仍可以逐 channel 学习。它放在 attention 和 FFN 的前后，为 block 内局部传播提供独立路径。它操作当前并行 hidden，不依赖已经采样出的前驱 token，因此不会增加 AR backbone 次数。↗ DFlash 2 · 作者技术博客，2026-08-18

C(x)t,c = Σj=0…k−1 [bj,c + Δt,j,group(c)] · xt−j,c
x′ = x + Cout(Attention(Cin(Norm(x))))
x″ = x′ + C′out(FFN(C′in(Norm(x′))))

LiteSpec 的 DFlashGroupedConv 支持可配置 taps / group size；一个 projection 从该子层归一化后的输入生成 in/out 两侧动态 kernel。finish 使用之前算出的 out coefficients，而不是从 attention 输出重新算 kernel。基础 kernel 初始化为 identity、动态投影初始化为 0，使新增模块初始近似恒等。↗ litespec/modeling/draft/dflash2.py:29 ↗ litespec/modeling/draft/dflash2.py:142

实现会 reshape 成 [batch, n_blocks, block_size, groups, group_size] 后做移位，明确隔离训练中的多个 blocks。块内第 0 位为 anchor，第一预测位可以读到 anchor 表征；不能跨 block 读上一块尾部。官方轻量推理示例直接沿序列移位，因此移植其函数到多 anchor 训练时应保留 LiteSpec 的分块处理。↗ dflash/model.py:492

配置契约

local_operator = none | dynamic_depthwise_conv
placement = attn_pre_post + ffn_pre_post
kernel_size = 2 作为论文对应起点；要求 group_size | d、taps ≤ block width。固定 d 下增加的是局部计算与参数，不是宽度搜索。

组合边界

通常可与 MHA / MLA、DFlare 和多种 head 组合；是否提升需要消融。对 H-Spec / Mamba 的组合尚无等价性保证。卷积带来的 hidden 因果混合与 head 的 token 因果依赖是不同机制，不应合并成一个“causal”布尔值。

04 / Conditional prediction

统一的是 proposal 契约，不是 logits 相加

令 zt 为并行骨干经过基础 LM head 的 logits，ht 为其 hidden，yt−1 为此前真正选出的 token。训练可 teacher-force 前驱；推理必须使用当前 proposal 前缀，并在每个新 block 重置状态。

4.1 DSpark：Markov 与 RNN 都是 additive，但状态协议不同

ut = [st−1; E(yt−1); ht]
[graw, craw, oraw] = W ut + b
st = sigmoid(graw)⊙st−1 + (1−sigmoid(graw))⊙tanh(craw)
z′t = zt + W₂ tanh(oraw)

这是 DSpark 论文和公开实现的 RNN 形式；output 分支由包含旧 state 的同一 ut 得到，不能擅自替换为 W₂s_t。LiteSpec 的单步 compute_step_bias 路径不足以表达跨步状态，统一接口必须显式传入 / 返回 state。原论文还包含 confidence-scheduled verification：这是另一个 verifier budget / stopping policy，不能把它与 Markov head 的结构贡献绑定。↗ DSpark · 2026-07 ↗ litespec/modeling/draft/dspark.py:144

4.2 Selector：候选分布与 full-vocab 分布必须区分

St(a,b) = zt,b + ⟨Eprev(a) ⊙ Whht, Enext(b)⟩，b ∈ TopK(zt)

LiteSpec 的 build_lattice 构造前后候选对分数，select_path 依据实际前驱逐步贪心 / 采样。它不是 Viterbi 全局最优路径算法。官方 Python 参考实现则在循环内计算实际前驱那一行；作者博客描述的并行 pair scoring 与这份简单参考实现的调度方式不同，报告不把两者当成同一份高性能内核。↗ litespec/modeling/draft/dflash2.py:200 ↗ dflash/model.py:515

当前训练严格使用 unary top-K：标签不在候选内时不给 selector CE 梯度，基础预测目标仍负责提高 recall；标签在候选内才计算条件分类。需分别记录 recall@K、候选内准确率、真实生成 acceptance。只报候选内准确率会掩盖候选覆盖不足。↗ litespec/core/dflash2.py:16

集成风险：softmax 应作用于实际候选分数，返回 candidates 与对应 q，而不是基础 full-vocab logits。训练给所有位置的前驱 token 与推理生成前缀不同，评估必须走完整顺序路径。selector 是受限支持集分布；与 full-vocab KL、BV 等目标组合需要显式处理候选外概率及零概率路径。

4.3 DLite：把“最终 head”与“基础辅助 head”分离

本地实现中 recurrence 只接收 [s_prev, prev_embedding]；更新后的 state 才与 ht 通过线性层融合，再经过 output projection。它与 DSpark 把 ht 放入 recurrent update 的方式不同。现有训练代码可另外计算 base LM CE 辅助项，但辅助项的存在不意味着最终 logits 是两者之和。↗ litespec/modeling/draft/dlite.py:34 ↗ litespec/core/dlite.py:442

建议 head 输出：ProposalDistribution（dense 或 sparse candidate support）+ HeadState + 可选 base logits / diagnostics。对训练增加 score_teacher_path，对推理增加 sample_step。让 verifier 只消费实际 q，而不猜测每种 head 的数学意义。
05 / Objective design

从逐 token 拟合，到 block 接受，再到跨轮效率

统一记号：p 为 target 条件分布，q 为最终实际 proposal 条件分布，y 为训练轨迹 token；B 为预测 token 数，不含 anchor。LiteSpec 多处 block_size 包含 anchor，因此对应 B=block_size−1。所有新目标都应通过显式 layout 获取预测范围，避免 off-by-one。

5.1 D-PACE：实现简单，归一化不能随意改

q̃i = (1−a)qi(yi) + a
Pm = Πi≤mq̃i；wj = stopgrad(Σm≥jPm)
L = Σj wj [−log qj(yj)]

官方代码用 exp(-CE) 得到 q(y)，对平滑概率做 cumprod，再 reverse-cumsum。无效位置在乘积内设 1、在求和内设 0；权重计算放在 no_grad 下。它平滑的是权重里的概率，CE 本身不做 smoothing。a=0 时 detached weighted CE 与负 confidence-prefix surrogate 的梯度对应；a>0 是经过设计的训练启发式，不能再宣称仍是原 surrogate 的精确梯度。↗ specforge/core/dflash.py:234

关键代码差异：官方 D-PACE 分支最后除以 batch size；原 DFlash 分支除以权重和。若接入 LiteSpec 统一 reducer 后直接用 Σw 作分母，会改变其梯度尺度和不同样本的相对作用。建议同时支持 paper_batch_sum 与明确命名的 normalized variant，先复现前者，再做自己的归一化消融。↗ specforge/core/dflash.py:365

不要默认将固定指数衰减与 D-PACE 相乘；它本来就是替换固定权重的方案。与 RNN head 组合时 q(y) 应来自 teacher-forced 的最终 head。若 selector 标签落在 top-K 外，q(y)=0，直接 log 会无穷：保留 base CE + covered selector CE 或另设计平滑支持集，并将偏离原目标的部分明确记录。

5.2 BV：必须保留 prefix 状态与真实 proposal 条件分布

r0=1，ri=Πj≤i qj(yj)/pj(yj)
Ai=min(1,r1,…,ri)
LBV=1−Ey∼p[ΣiAi]/B
Āi=Σvmin(Ai−1pi(v), ri−1qi(v))

最后一行是积分掉当前 token 的 vocabulary-integrated score；prefix r/A 仍沿采样轨迹更新，不能改为 Ā 的累计乘积。论文主实验用其 block-log surrogate，并逐步把 prefix 聚合从几何均值过渡到算术均值；E[−log τ̂] 与 −log E[τ̂] 不是同一目标。训练实现应明确选择 sampled-label 还是 integrated estimator，分别标记 loss value 与 gradient surrogate。↗ Block Verification-aware Loss · 2026-09

落地要求：累计 ratio / running minimum 用 FP32 log-space；prefix state 必须保留梯度。teacher 轨迹须由与分母 p 相同的分布产生（含温度、截断等）；任意聊天数据或 greedy 数据不能直接继承 unbiased 结论。DSpark / DLite 必须沿真实 teacher prefix 计算条件 q；测试要覆盖 q=0、支持集不匹配、padding、EOS 和梯度 tie。

它对应 block verification 的目标，不能把“block draft”误当“block verification”。用逐 token verifier 也可以作为迁移实验，但理论目标已不完全匹配。复现建议先对 dense-support head 接入 BV，再研究 selector；后者的 top-K 支持集随参数离散变化，原结论的可微实现条件不能自动成立。

5.3 EDR：不是另一个普通 weighted TV 开关

EDR 在完整 target rollout 上考虑各个可能 round start，利用 Bellman / occupancy 动态规划得到占用权重与后续价值；EOS-aware rejection cost 还要区分停止 token。官方实现先计算紧凑的 [trajectory_len, B] statistics，再在 CPU 上做 detach 的 DP，梯度只走局部 cost / acceptance 项；其中 teacher 路径统计使用 min(q(y)/p(y),1)，不要替换为实际 proposal 验证中常见的 p/q。↗ angelspec/models/ops/edr.py:252 ↗ angelspec/models/ops/edr.py:1430

gradient-surrogate = Σstates stopgrad(occupancy) · [cost + acceptance · stopgrad(continuation_advantage)]

edr_surrogate_sum 的标量值本身不是预计 target-pass 数，日志需另报 DP 的真实指标。其抽样版从 round starts 按概率采样并做 inverse-probability 修正；不能用现有随机 anchor 平均权重代替。官方当前 recipes 为已训练 draft 的微调，不以此保证从零训练稳定。↗ angelspec/models/ops/edr.py:1580 ↗ angelspec/models/ops/edr.py:1701

5.4 Loss engine 必须知道 reduction 的作用范围

当前 checkpointed_chunk_reduce 假定每个 chunk 的输出可加。CE/KL/TV 可以逐 token 分块；D-PACE、E2E-TV、BV 不能把一个 block 切碎后独立算 prefix；EDR 的状态甚至跨 blocks。可沿 batch / 完整 anchor 分块，或先累积保持梯度的 compact statistics，再在完整 block / trajectory 上归约。vocab 分块也要保留全局 softmax normalization，不能对子 vocab 各自 softmax。↗ litespec/core/chunking.py:35

把 TokenLoss、PositionWeightPolicy、BlockObjective、TrajectoryObjective 分开注册；混合项分别携带 numerator、denominator 与 scope。现有 TrainingOutput 仅有一组总 loss_terms，需定义多项不同分母的聚合规则后再扩展，避免 DDP / accumulation 使结果依赖 chunk 切法。↗ litespec/core/outputs.py:18

7.2 必须分开的评估指标

  • 质量：逐位置条件接受率、整个 prefix survival、平均接受 draft tokens；是否含 bonus / correction 单独注明。Teacher-forcing token accuracy 不能代替真实 rollout acceptance。
  • 性能：每轮 target verification、draft backbone、head、selector、indexer、KV 处理分别计时；报告端到端 tokens/s 与延迟，而非仅接受长度。
  • 资源：target KV 与额外 draft KV / indexer cache 分开统计；峰值激活、参数量、训练 logits 内存、feature I/O。
  • 实验语境：greedy 与 stochastic 分开；记录 T / top-p / top-k / penalty、上下文长度、batch / concurrency、kernel、硬件和模型版本。

7.3 会真正检出问题的验证项

  1. 遮罩：用两个 documents、多个 anchors 和尾部 padding 构造 tiny case；扰动未来 target hidden/KV 后，当前 block 输出不得变化。验证 full / legacy SWA / 新解耦 SWA 的真值表。
  2. Cache：prefill+decode 与一次性 reference 对齐；接受 0 / 部分 / 全部、EOS、拒绝后重新生成时 crop 正确；借用 target KV 不产生写入。
  3. Heads：teacher-forced 整块输出与逐步输入同一 token 前缀的输出一致；RNN 每块 reset；selector 返回的 q 在候选集上归一化，并与实际 sample 所用 q 一致。
  4. Loss：p=q 时 TV=0、NLA=0；L1=2TV；有限差分检查新增 block loss；D-PACE a=0 的梯度关系、padding identity 和官方 batch reduction；BV 的 B=1 integrated loss 退化到 TV。
  5. Verification：小词表短序列穷举 / Monte Carlo 检查最终分布；不能仅凭 accepted length 正常就断言无损。
  6. DSA：K 覆盖全部合法 keys 时与相同 mask 的 dense attention 对齐；K 很小时无 padding 泄漏；indexer KL 与主 loss 的梯度隔离符合设计。

本报告列出的是后续框架验收要求。本轮已完成文本与源码核对、引用检查、报告显示检查，以及 5 项纯 Python 小规模公式检查：L1/TV 尺度、B=1 的 BV 退化、BV prefix minimum、D-PACE padding 和 a=0 梯度关系。公式检查记录。没有执行上述模型级 / GPU 验证。
